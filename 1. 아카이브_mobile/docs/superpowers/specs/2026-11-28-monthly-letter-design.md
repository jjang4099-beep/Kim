# 나의 역사 — 월간 편지 · 설계

- 날짜: 2026-11-28 · 상태: **승인**(사용자, 채팅) · 같은 날 개정: 사용자 "매달은 이상하다" → **앱은 분기 편지**(YYYY-Qn, `GET /api/letter/:period`), 존댓말, 내가 남긴 문장을 편지보다 먼저, 편지 3~4문장
- 범위: 1단계 **월간 편지**(앱 학습 관리). 분기 편지·연말 특별호·매달 1일 알림은 다음 단계.

## 왜
앱의 본질은 "나의 역사, 나의 기록"(제품 방향 11-28). 지금의 "지식 결산"(개수·분야·키워드 통계 + AI 서너 줄)은 정보만 있고 "정말 잘했다"는 마음이 오지 않는다.
매달 내 기록으로 "이번 달의 당신"을 아카이브다운 잡지·편지 한 편으로 돌려줘서, 내가 가치 있는 사람이라는 걸 스스로 확인하게 한다.

## 목표 · 비목표 · 반목표
- 목표: 달을 고르면 잡지 한 편이 화면 가득 열린다 — ① 표지(“2026년 11월의 당신”, 그달 사진 한 장, 한 줄 제목) ② 편지(4~5문장)
  ③ 숫자(기록한 날·받은 지식·서재에 담은 것·남긴 생각·영어 표현) ④ 걸어온 길(지식 지도 테마별 받은 편) ⑤ 내가 남긴 문장(생각 인용 2~3)
  ⑥ 장면(일상·여행 기록 사진·장소).
- 비목표: 분기·연말 특별호, 알림, PC 연대기 변경(다음 단계).
- 반목표: 지어낸 사실, 꾸짖는 어조, 차트 대시보드, 라벨 앞 이모지.

## 방식 (사용자 선택: B 잡지·편지형)
- A 넘기는 카드형(이벤트 느낌) · C 차트형(감동 약함) → 탈락. B 채택.

## 결정
- **원칙**: 기록에 있는 것만 말한다(프롬프트로 강제, 입력은 실제 기록만). 기록이 적은 달은 짧은 편지("쉬어 간 달에도 이것을 남겼다"), 꾸짖지 않는다.
  AI가 실패하면 기록으로 만든 짧은 대체 편지. 기록이 바뀔 때만 다시 쓴다(지문 캐시).
- **데이터**: 내 기록 = `ItemsDB.getItemsByUser(userId, PROFESSIONAL)`(그달 date) — 일상(contentType life: text·life.location·life.photos), 서재에 담은 지식(feedData), 생각(myInsight, '['로 시작하는 자동 문구 제외).
  받은 지식 = 배달 프로필(`_questGot`, 같은 주제 합치기 접음) 중 그달 받은 것, 지식 지도 단계로 묶음(`buildQuest`).
- **서버**: 순수 함수 `public/lib/monthlyLetter.js`(사실 모으기·프롬프트·대체 편지·지문) + `GET /api/letter/monthly/:ym?mode=` (requireAuth, 캐시 `SummariesDB` type `letter-monthly`, period `ym@지문`).
  편지 모델 `claude-opus-5`(연말 회고와 같은 선택, 월 1회 수준), 출력 첫 줄 = 제목, 나머지 = 편지.
- **앱**: 학습 관리의 "지식 결산" 블록 → "나의 역사"(이번 달 + 지난 5달 고르기) → 전체 화면 잡지(`#letterView`). 색·글꼴은 앱 토큰(--surface·--bg·--text-*·--accent·--gold·--border), 라이트·다크.
- 옛 `/api/summary`·`loadSummary` 코드는 남겨 두되 화면에서 부르지 않는다.
