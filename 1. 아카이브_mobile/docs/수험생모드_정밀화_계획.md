## 1. 문제 정의 — "정밀화"가 가리키는 것

오답 사진 분석 기능 자체는 **이미 구현돼 있다**(`server.js`의 Gemini 분석 프롬프트).
정답·풀이단계·필요개념·오답진단·보완점·연관개념까지 뽑아낸다. 새로 만들 것이 아니다.

진짜 병목은 세 가지다.

### ① 단원명이 AI 자유 서술이라 누적이 안 된다 ★ 최우선

`GET /api/exam/weakness-analysis`는 `${subject}::${unit}`으로 집계하는데,
`unit`이 AI가 매번 새로 쓰는 문자열이다.

```
"수열 > 등차수열의 합"   ← 오답 1
"수열"                   ← 오답 2   (같은 단원인데 다른 키)
"등차수열"               ← 오답 3
```

→ 오답을 30개 모아도 "네 약점은 여기다"가 나오지 않는다.
**교육과정 단원 코드를 고정하고 AI가 자유 서술 대신 그 목록에서 고르게 해야 한다.**

같은 병이 한국사 배달에도 이미 있다 — `era_label`이
`일제강점기`/`일제 강점기`, `조선 전기`/`조선전기`, `통일신라·발해`/`통일신라`로 흩어져
**9~10개 시대가 15개 라벨로** 쪼개져 있다.

### ② 과목을 학생이 직접 고른다

`js/add.js`가 `ExamMob.selectedSubject || 'math'`를 보낸다.
기본값이 `math`라 국어 오답을 그냥 올리면 수학으로 태깅된다. 사진만 봐도 AI가 판별할 수 있다.

### ③ 개념 DB에 수학·국어가 0개다

| 과목 | 현재 보유 |
|---|---|
| 영어 | 210단어 / 42팩 |
| 한국사 | 96개 |
| 과학 | 208개 (2015 개정 체계) |
| **수학** | **0** |
| **국어** | **0** |

오답에서 `등차수열`이 개념으로 잡혀도 연결할 콘텐츠가 없어서, 지금은 유튜브 검색 링크로 넘기는 게 전부다.

## 2. 핵심 설계 — 단원 코드로 조인한다

개념 매칭을 **AI 문자열 비교가 아니라 단원 코드 조인**으로 바꾸는 것이 이 작업의 뼈대다.

```
오답 사진 ──▶ AI가 unitCode 하나를 고른다 (자유 서술 아님)
                    │
                    ├──▶ 취약점 집계 (같은 코드끼리 정확히 쌓인다)
                    │
                    └──▶ 같은 unitCode를 가진 개념 카드를 자동으로 붙인다
                                  ▲
                         개념 DB도 unitCode를 갖는다
```

AI가 개념명을 뭐라고 쓰든 상관없어진다. 코드가 같으면 연결된다.

### 단원 코드 규격

```js
{
  code:     'MATH_ALG_03_02',   // 과목_과정_대단원_중단원
  subject:  'math',             // EXAM_SUBJECTS 키
  course:   '대수',              // 과목(교육과정상 과목명)
  unit:     '수열',              // 대단원
  topic:    '등차수열',           // 중단원 — AI가 고르는 최소 단위
  grade:    '고2',
  inCsat:   true                // 2028 수능 출제범위 여부
}
```

`code`가 유일 키. 저장 위치는 `public/data/exam_db/curriculum.json` (읽기 전용 참조 데이터).

## Phase 2 — 오답 분석을 트리에 물리기

`server.js`의 오답 분석 프롬프트를 고친다. **콘텐츠가 없어도 즉시 효과가 나는 단계라 먼저 한다.**

### 2-1. 과목 자동 판별
프롬프트에 `subject` 필드를 추가하고, 사진을 보고 AI가 판단하게 한다.
학생이 고른 값은 **힌트로만** 쓰고, AI 판단과 다르면 AI를 따른다(단, 학생이 명시적으로 바꾼 경우는 존중).

### 2-2. `unitCode` 강제
```
"unitCode": "아래 목록에서 정확히 하나만 고르세요. 해당하는 것이 없으면 'ETC'.",
"unit": "(사람이 읽을 자유 서술 — 표시용. 집계에는 쓰지 않는다)"
```
프롬프트에 해당 과목의 코드 목록을 끼워 넣는다(과목 필터 후 20~40줄 수준).

### 2-3. 집계 키 교체
`weakness-analysis`의 집계 키를 `${subject}::${unit}` → **`unitCode`**로 바꾼다.
기존 오답(코드 없음)은 `ETC`로 묶이되 **지우지 않는다**.

### 완료 조건
- [ ] 같은 단원 오답 3장을 올리면 취약점에서 **한 칸으로 합쳐진다**
- [ ] 국어 문제를 과목 선택 없이 올려도 `korean`으로 잡힌다
- [ ] 기존 오답이 깨지지 않는다

## Phase 3 — 오답노트 출력 (문제지 / 답지 분리)

> **오답노트의 목적은 '보관'이 아니라 '다시 푸는 것'이다.**
> 문제지에는 정답이 보이면 안 되고, 답지는 별도로 붙어야 한다.

### 3-0. 현재 상태

`GET /api/exam/wrong/export-pdf`가 이미 있다 — A4 세로, 한 페이지에 2×2(4문제), 사진만.
즉 **문제지는 이미 동작한다.** 빠진 것은 세 가지다.

| 빠진 것 | 내용 |
|---|---|
| 답지 | 정답·풀이·개념이 PDF에 아예 안 들어간다 |
| 한글 | `StandardFonts.Helvetica`라 PDF 내부 텍스트가 **영문·숫자만** 가능했다 |
| 날짜 | 과목 필터만 있고 기간 선택이 없다 |

### 3-1. 한글 폰트 임베딩 — 해결 확인됨

`@pdf-lib/fontkit` + `public/fonts/NotoSansKR-Regular.otf`(SIL OFL, 재배포 가능).
`embedFont(bytes, { subset: true })`로 **쓴 글자만 담으면** 원본 4.4MB 폰트로도 PDF는 40KB 수준.
스파이크로 실제 한글 출력까지 확인했다.

> 주의: `Dockerfile`은 `public/`만 복사한다. 폰트는 반드시 `public/fonts/` 아래에 둔다.
> `registerFontkit`은 PDFDocument마다 호출해야 하고, 폰트 바이트는 모듈 로드 시 한 번만 읽어 캐시한다.

### 3-2. 출력 구성

한 번의 다운로드에 **문제지를 앞에 몰고 답지를 뒤에 몰아서** 넣는다.
답지를 떼어내거나 안 보면 그대로 문제지가 된다.

```
[표지]    과목 · 기간 · 총 문제 수
[문제지]  1~N번 문제 사진 (2×2) — 정답·풀이 없음, 번호 옆에 날짜·단원 라벨만
[답지]    1~N번 — 정답 / 풀이 단계 / 필요 개념 / 내가 틀린 지점 / 보완할 것
```

쿼리 파라미터:

| 파라미터 | 값 | 설명 |
|---|---|---|
| `subject` | `all` \| 과목키 | 기존 유지 |
| `from` / `to` | `YYYY-MM-DD` | 신규 — 기간 지정 |
| `period` | `today` \| `week` \| `month` \| `all` | 신규 — 프리셋 (from/to가 있으면 그쪽이 우선) |
| `answers` | `1` \| `0` | 신규 — `0`이면 **문제지만** (기본 `1`) |
| `unitCode` | 단원 코드 | 신규 — Phase 2 이후. "이 단원만 다시 풀기" |

### 3-3. 날짜별 정리

사진을 공유하면 `date`가 박히므로 서버 데이터는 이미 날짜를 갖고 있다. 필요한 건 보여주는 쪽이다.

- 오답 서재 목록을 **날짜 섹션으로 묶어서** 보여준다(지금은 평면 나열).
- 문제 번호는 기간 내 **오래된 순**으로 매긴다(기존 정렬 유지).
  문제지와 답지의 번호가 반드시 일치해야 한다.

### 3-4. 답지 내용 원천

모두 `wrongAnswer`에 이미 있는 값이다. 새로 AI를 부를 필요 없다.

| 답지 칸 | 원천 필드 |
|---|---|
| 정답 | `wrongAnswer.answer` |
| 풀이 단계 | `wrongAnswer.modelSteps[]` |
| 필요 개념 | `wrongAnswer.requiredConcepts[].term` / `.desc` |
| 내가 틀린 지점 | `wrongAnswer.solutionReview.errorStep` / `.diagnosis` (있을 때만) |
| 보완할 것 | `wrongAnswer.whatToReinforce` |
| 단원 | `wrongAnswer.unitCode` → `curriculum.json`에서 라벨 조회 (Phase 2 이후) |

> 미분석(`analysisStatus !== 'done'`) 문제는 문제지에는 넣고 답지에는
> "아직 분석되지 않음"으로 표시한다. 조용히 빼서 번호를 어긋나게 만들면 안 된다.

### 완료 조건
- [ ] 답지의 한국어 해설이 글자 깨짐 없이 출력된다
- [ ] 문제지에 **정답이 한 글자도 노출되지 않는다**
- [ ] 문제지 번호와 답지 번호가 정확히 대응한다
- [ ] `answers=0`으로 문제지만 뽑을 수 있다
- [ ] 기간을 골라 그 기간 오답만 나오게 할 수 있다
- [ ] 오답이 0건인 기간을 고르면 빈 PDF가 아니라 안내가 나온다

## Phase 4 — 개념 DB 채우기

### 4-1. 기존 과학 208개 재분류
`물리학I`·`화학I`·`생명과학I`·`지구과학I` → 통합과학1·2 `unitCode`로 매핑.
- 매핑되는 것(예: 뉴턴 운동 법칙 → `시스템과 상호작용 > 중력장 내의 운동`)은 코드만 부여
- 통합과학 범위를 벗어나는 것(현대 물리 등)은 **삭제하지 말고** `deprecated: true`로 두고 배달 풀에서 제외

### 4-2. 신규 작성 우선순위
| 순서 | 대상 | 예상 분량 |
|---|---|---|
| 1 | 수학 — 대수 · 미적분Ⅰ · 확률과 통계 | 성취기준 54개 × 2~3 = **120~160개** |
| 2 | 통합과학 부족분 | 재분류 후 빈 중단원 채우기 |
| 3 | 통합사회 | 대단원 10개 × 6 = **60개** |
| 4 | 영어·한국사 보강 | 기존분 코드 정리 + 빈 곳 |

### 4-3. 개념 카드 스키마
```json
{ "id": "EC_###", "unitCode": "MATH_ALG_03_02", "subject": "math",
  "title": "등차수열의 합", "summary": "핵심 설명 3~5문장",
  "key_formula": "S_n = n(a_1 + a_n)/2",
  "key_point": "시험에서 바로 쓰는 한 줄",
  "common_mistake": "학생들이 여기서 가장 많이 틀린다 — 1~2문장",
  "exam_tip": "출제 포인트" }
```
> `common_mistake`가 기존 스키마에 없던 필드다. 오답 카드와 붙었을 때 가장 쓸모 있는 칸이라 넣는다.
> 수식은 콘텐츠 가이드와 동일하게 **LaTeX 금지, 평문 표기**(`3/2`, `x^2`, `√2`, `π`).

### 완료 조건
- [ ] 모든 개념 카드가 유효한 `unitCode`를 갖는다 (`ETC` 없음)
- [ ] 2028 수능 범위 중단원 중 개념 카드가 0개인 곳이 없다

## Phase 5 — 오답 ↔ 개념 연결

오답 상세 화면에서 `unitCode`가 같은 개념 카드를 자동으로 붙인다.
AI가 뽑은 `requiredConcepts`(자유 서술)는 **설명용으로 그대로 두고**, 연결은 코드로 한다.

- 오답 카드 하단: "이 단원 개념 다시 보기" → 해당 `unitCode` 개념 카드 목록
- 개념 카드에서 역방향: "이 단원에서 내가 틀린 문제 N개"
- 유튜브 검색 링크는 **개념 카드가 없을 때의 폴백**으로 내린다

### 완료 조건
- [ ] 수학 오답 한 장에서 개념 카드까지 탭 두 번 안에 도달
- [ ] 개념 카드가 없는 단원에서도 화면이 깨지지 않는다(폴백 동작)

---

## Phase 6 — 취약점 리포트 정밀화

Phase 2로 집계가 정확해진 뒤에야 의미가 있다.

- 단원별 오답 수 + **최근 추세**(늘고 있는지 줄고 있는지)
- 2028 수능 범위 대비 **커버리지**: 안 건드린 단원 / 반복해서 틀리는 단원
- 복습 큐(`reviewEase`·`reviewAt`)를 단원 단위로 묶어 제시

---

## 작업 순서 요약

```
Phase 1  단원 트리 고정        → 기존 동작 무영향 확인
Phase 2  오답 분석을 트리에 물림 → 콘텐츠 없이도 즉시 효과 ★
Phase 3  오답노트 출력         → 문제지/답지 분리 · 한글 PDF ★
Phase 4  개념 DB (수학부터)     → 가장 오래 걸림
Phase 5  오답 ↔ 개념 연결
Phase 6  리포트                → 마지막
```

**Phase 1~3이 "오답노트"의 본체다** — 단원이 정확히 쌓이고, 다시 풀 수 있는 종이가 나온다.
Phase 4는 분량 싸움이라 나눠서 계속 진행하면 된다.

## 하지 말 것

- 기존 오답 데이터의 필드 이름 변경·삭제 (`wrongAnswer.unit`은 표시용으로 남긴다)
- 2015 개정 콘텐츠(과학 208개) 삭제 — `deprecated` 플래그로만 처리
- 단원 코드 없이 개념 카드 추가 (다시 흩어진다)
- 국어 콘텐츠 선행 (이번 라운드 범위 밖)
- 모드 격리 위반 — 수험생 콘텐츠는 `exam_db`에만, `knowledge_db`/`work_db`와 섞지 않는다.
- **문제지에 정답·풀이를 노출하기** — 다시 풀 수 없으면 오답노트가 아니다.
- 폰트를 `public/` 밖에 두기 — Docker 이미지에 안 들어가서 운영에서만 PDF가 깨진다.
