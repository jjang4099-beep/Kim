# 지식 배달 콘텐츠 생성 가이드 (매일 생성용)

> 직장인/수험생 배달 콘텐츠를 **어디에 · 어떤 형식으로 · 어떤 id로** 추가하는지의 단일 기준 문서.
> 매일 조금씩 생성할 때 아래 §4의 "복붙 프롬프트"를 다른 대화에 붙여넣고 주제만 바꾼다.
> **기준일 2026-06-24** — 아래 "다음 id"는 이 날짜 기준. 새 작업 전 `npm run scan-ids`로 항상 재확인.

---

## 1. 저장 위치 (3개 폴더)

| 모드 | 폴더 | 적재 키 |
|---|---|---|
| **직장인** | `public/data/knowledge_db/*.json` | english_theme_packs · english_expressions · chinese_expressions · history_facts |
| **직장인 (신규)** | `public/data/work_db/*.json` | classic_quotes(고전) · idiom_cards(고사성어) · daily_insights(인사이트) |
| **수험생** | `public/data/exam_db/*.json` | exam_vocab_themes · exam_history_items |

- 서버가 폴더 전체 `.json`을 읽어 메모리/SQLite에 적재(중복 id는 자동 스킵). 배달은 AI 호출 없이 회전 서빙.
- `archive.db` · `dailyFeeds.json` 은 **런타임 생성물 — 직접 편집 금지.** 콘텐츠는 항상 위 시드 폴더에만.
- **모드 격리:** 수험생 배달은 `exam_db`만 읽는다. `knowledge_db`·`work_db`(직장인)는 수험생에 **절대 안 뜸**. 직장인 콘텐츠를 `exam_db`에 넣지 말 것(그 반대도).

> ⚠️ 폐기됨(더 넣지 말 것): 옛 `idioms_and_quotes`(IQ_) / `quote_daily`(명언) — 고사성어는 이제 `work_db/idiom_cards`로, 명언은 고전(LIBER)·인사이트로 대체됨.

> 📦 **배달 피드는 3개다**(2026-09-13~): 영어(en_expr) · 미국 시황(us_market) · **지식 한줌(daily_knowledge)**.
> 지식 한줌은 **하루 두 장**(09-28~): ① 역사 이야기 매일(daily_knowledge) ② 오늘의 지혜(daily_wisdom) — 고사성어·인사이트·고전이 하루씩 돌아간다.
> 10-05~ 역사는 **연재**(그리스 10편 → 로마 14편 → 고려 10편 → 전국시대 12편)로 이어서 나가고, 카드마다 **깊이 읽기**(배경·용어·그 후·써먹는 한마디)가 붙는다 → §4-E.

## 2. 절대 규칙
1. **최상위 키 이름 정확히** (오타 시 미적재).
2. **id 전역 고유** — 이미 쓴 번호 재사용 금지(`INSERT OR IGNORE`라 조용히 누락). 항상 "다음 id"부터.
3. **파일 이름 자유** (폴더 전체를 읽음). 관례: knowledge_db=`batch_NN_주제.json`, work_db=`<타입>_NN.json`, exam_db=`vocab_NN_csat.json`/`history_NN_kr.json`.
4. work_db 항목은 `targetMode: "work"`, `used: false` 고정.
5. JSON에 `meta`(작성일·주제 메모)는 넣어도 무시됨 — 자유롭게.
6. **사실과 전승을 섞지 말 것.** 후대에 덧붙은 일화는 "전해진다"로 밝힌다.
   재미를 위해 확인 안 된 이야기를 사실처럼 쓰면 지식 앱의 신뢰가 무너진다.
6. **같은 표현을 다시 넣지 말 것** — 중복 배달 방지는 `item_id`로만 판단해서, 같은 표현이
   다른 id로 여러 개 있으면 60일 안에 여러 번 배달돼도 시스템이 눈치채지 못한다.
   (2026-09: 평면 풀 588개 중 119개가 중복이었고 `think outside the box`는 8번 들어 있었다)
7. **`theme_category`는 `business_meeting`/`daily_travel`/`drama_spoken` 셋 중 하나만.**
   `level`은 `beginner`/`intermediate`/`advanced` 셋 중 하나만. 목록에 없는 값을 쓰면
   어떤 설정으로도 매칭되지 않아 콘텐츠가 통째로 죽는다(부팅 로그에 경고가 뜬다).

### (B) 직장인 — 고사성어  → `work_db/idiom_cards.json`
```
SJ 아카이브 직장인 배달 "고사성어" 콘텐츠를 생성한다. JSON 한 덩어리만 출력, 설명·마크다운 금지.
- 위치: public/data/work_db/ 의 .json, 최상위 키 "idiom_cards"
- id: IDC_<다음 번호>부터 전역 고유(현재 다음 IDC_003).
- 직장·비즈니스 관점으로 풀이. 성어 5개.
- 주제 영역: <여기에. 예: "리더십·전략">
스키마:
{ "meta":{"topic":"...","created":"YYYY-MM-DD"},
  "idiom_cards":[ {"id":"IDC_###","idiom":"새옹지마","hanja":"塞翁之馬","meaning":"뜻 1~2문장","origin":"유래 200~320자 — 아래 기준 참고","example":"이 성어를 쓴 실제 문장 1개","modernUse":"직장에서 쓰는 구체적 상황 2~3문장","contextType":"work","tags":["인내","전략"],"targetMode":"work","used":false} ] }
```

> **고사성어 유래(`origin`)는 출전만 대고 끝내면 안 된다.**
> 고사성어의 값어치는 **장면**에 있다 — 누가 무엇을 했는지가 있어야 기억에 남는다.
> - 나쁨: *"《논어》에서 공자가 한 말이다."* (83자, 이야기가 없음)
> - 좋음: *"끌려가며 한신은 '날쌘 토끼가 죽으면 좋은 사냥개는 삶아 먹힌다'고 탄식했다고 한다. 원래 이 말은 월나라 범려가 친구 문종에게 보낸 편지에 나온 표현으로, 범려는 떠나 살아남았고 문종은 남아 죽었다."*
> - 사람 이름과 행동이 들어간 장면을 쓴다. **200~320자.**
> - 고사성어 원전은 설화·전승인 경우가 많으므로 **"~고 한다 / 전해진다"**로 쓴다(절대 규칙 6).
> - `modernUse`(직장 적용)와 겹치지 않게 한다.
>
> 현재: 104개 중 유래 200자 이상은 **20개**. 중앙값 106자 — 나머지는 아직 짧다.

### (D) 직장인 — 영어 테마팩  → `knowledge_db/batch_NN_*.json`
```
SJ 아카이브 직장인 배달 "영어 테마팩"을 생성한다. JSON 한 덩어리만 출력, 설명 금지.
- 위치: public/data/knowledge_db/ 의 .json, 최상위 키 "english_theme_packs"
- id: PACK_EN_<다음 번호>부터(현재 다음 PACK_EN_095), 표현 id "<팩id>_01"…"_05". 전역 고유.
- **예문(`example`)은 반드시 학습자가 그대로 말할 수 있는 1·2인칭 문장**(I/we/you/let's). "High-performing employees take ownership…", "She took the lead…" 같은 3인칭 서술·일반론은 금지 — 10-05 점검에서 이런 예문 108개를 고쳤다.
- **대화(`dialogue`)는 반드시 문자열**(`A: …\nB: …` 3~4턴). 객체(`{"A":…,"B":…}`)로 쓰면 화자당 한 줄만 들어가 2턴으로 잘린다(팩 035~045가 이 상태).
- 새 팩을 넣기 전 **기존 팩·평면 풀과 근사 중복 검사**(핵심어 80% 이상 겹침). 10-05에 팩-팩 7쌍을 새 표현으로 교체하고 평면 풀 중복 24개를 삭제했다.
- 한 팩 = 실전 상황 테마 1개 + 표현 5개 + 마스터 단락. dialogue 3~4턴(\n 줄바꿈, 객체 `{"A":"...","B":"..."}` 형태 금지 — 문자열로), nuance는 "왜 이 표현"을 2~4문장.
- `example_ko`(예문 한국어 해석) 필수 — Example 섹션 길이 문제로 dialogue 전체는 번역 안 하고 예문 한 줄만 번역해서 붙인다(07-26 결정).
- **`theme_category` 필수(07-27 결정)** — 관리 화면 "집중 테마" 체크박스와 실제로 매칭되는 값이어야 배달에 반영됨. 반드시 다음 3개 중 하나:
  - `business_meeting` — 비즈니스 영어 전반(회의·이메일·협상·리더십·면접 등 직장 상황 통칭. 지금까지 만든 팩 대부분이 여기 — 07-27 기준 40개 중 37개)
  - `daily_travel` — 일상/여행 회화(09-27 기준 17개: 초급 6 · 중급 6 · 고급 5 — batch_40·45·50)
  - `everyday_situations` — **🗓 상황별 표현(09-28 신설)**: 날씨·가게에서 살 때/팔 때·은행·미용실·전화·택배처럼 상황별로 떼어 낸 팩. 관리 화면 영어 테마에 체크박스로 추가됨. 09-28 기준 8개(초3·중4·고1, batch_65). 다음 후보: 병원 접수·집 구하기·헬스장·세탁소·주유소.
  - `drama_spoken` — 미드 구어체(09-27 기준 21개: 초급 7 · 중급 9 · 고급 5 — batch_41·45·48·51). ⚠️ 평면 풀과 겹치지 않게 — batch_41 초안의 rain check·Spill it은 평면 풀에 이미 있어 교체했다.
  - (예전에 쓰던 `office_email`은 폐기 — business_meeting에 흡수됨. 새 콘텐츠에 쓰지 말 것)
- **`level`은 이제 3단계**: `beginner`(초급) / `intermediate`(중급) / `advanced`(고급). **같은 theme_category 안에서 레벨별로 짝을 맞춰 작성하는 게 원칙** — 어려운 단어로 바꾸는 게 아니라 "같은 실제 상황을 원어민이 얼마나 압축해서 말하는가"의 차이로 레벨을 가른다.
  예: 배를 탈 때 → 초급 "I want to **take a boat**." / 고급 "We're **boarding** at 9 AM." (같은 상황, board를 동사로 바로 쓰는 게 더 원어민스러움)
  → 새 테마팩을 만들 때는 가능하면 같은 theme_category에서 다른 level 팩도 같이(또는 다음 배치에) 만들어서, 그 카테고리를 어느 레벨로 골라도 팩이 있게 할 것. 특히 daily_travel·drama_spoken은 beginner가, business_meeting은 상대적으로 advanced가 부족하니 그쪽부터 채울 것.
- 주제: <여기에. 예: "재택·하이브리드 근무 커뮤니케이션">
스키마:
{ "meta":{"topic":"...","created":"YYYY-MM-DD"},
  "english_theme_packs":[ {"id":"PACK_EN_###","theme_key":"snake_case","theme_category":"business_meeting|daily_travel|drama_spoken","theme_title":"한국어 제목","theme_title_en":"English Title","level":"beginner|intermediate|advanced","delivery_date":null,
    "expressions":[ {"id":"PACK_EN_###_01","order":1,"expression":"...","meaning":"...","nuance":"...","dialogue":"A: ...\nB: ...","example":"...","example_ko":"예문 한국어 번역","practice":"..."} ],
    "master_paragraph":{"text":"5~7문장 영어","translation":"한국어 번역","highlights":["표현1","표현2"]} } ] }
```
> 영어 평면 표현(`english_expressions`, 다음 EN_326)·중국어(`chinese_expressions`, 다음 ZH_078)는 기존 batch 파일 스키마를 그대로 따른다. 이 평면 풀은 아직 theme_category 태깅 전이라(레벨만 필터링됨) 테마팩이 항상 우선 — 평면 풀은 테마팩 개수가 설정값보다 부족할 때 보충용으로만 쓰인다.

### (E) 직장인 — 역사·일반상식  → `knowledge_db/batch_NN_*.json`
```
SJ 아카이브 직장인 배달 "역사·일반상식" 콘텐츠를 생성한다. JSON 한 덩어리만 출력, 설명·마크다운 금지.
- 위치: public/data/knowledge_db/ 의 .json, 최상위 키 "history_facts"
- id: HI_<다음 번호>부터 전역 고유(현재 다음 HI_458). 항목 10개.
- 주제 영역: <여기에. 예: "화폐와 금융의 기원">
```

## 4-A2. 고전 배경·일화 (전량 완료 · 새 고전은 배경 포함해서 넣을 것)

> **왜:** 고전 카드에는 `context`(직장 적용)만 있고 **배경이 없었다.**
> 역사에는 `behind_story`, 고사성어에는 `origin`, 인사이트에는 `realLife`가 있는데 고전만 없었다.
> 조언만 있으면 읽히지 않는다 — 누가 어떤 처지에서 한 말인지가 있어야 문장이 살아난다.

### 진행 상황

| | 개수 |
|---|---:|
| 고전 전체 | 152 (근사 중복 14개 정리 후) |
| `backstory` 있음 | **152 — 전량** (2026-09-25 완료) |
| 남은 것 | 0 — 앞으로 추가하는 고전은 `backstory` 없이 넣지 말 것 |

> ⚠️ **같은 문장의 다른 번역을 중복으로 넣지 말 것.** 정확일치로는 안 잡힌다.
> 어린왕자 "가장 중요한 것은 눈에 보이지 않아"가 세 가지 번역으로 3개, 논어 학이편 1장이 3개 들어가 있었다.
> 새 고전을 넣기 전 **한글만 남긴 2-gram 유사도**로 기존 것과 겹치는지 확인한다.

### 카드에서의 순서
**배경이 먼저, 적용이 나중이다.** 카드는 `그때 무슨 일이` → `오늘의 나에게` 순으로 편다.
조언부터 나오면 읽히지 않는다.

### 작성 기준

- **장면 하나**를 넣는다. 추상적 소개가 아니라 기억에 남는 구체적 사실.
  - 좋음: *"아우렐리우스는 반란 가담자들을 용서하고 그들의 편지를 읽지 않은 채 불태웠다고 전해진다."*
  - 나쁨: *"그는 관용을 중시한 황제였다."*
- **`context`와 겹치지 않게.** `context`는 "그래서 나는 어떻게" 쪽이고 `backstory`는 "그때 무슨 일이" 쪽이다.
- ⚠️ **후대에 덧붙은 일화는 반드시 "전해진다 / 일화다"라고 밝힌다.**
  예컨대 히데요시가 노부나가의 짚신을 품에 품어 데웠다는 이야기는 널리 알려져 있지만
  당대 기록이 아니라 후대 전승이다. 사실과 전승을 섞으면 지식 앱의 신뢰가 무너진다.
- ⚠️ **출처가 잘못 알려진 명언은 배경에서 바로잡는다.** 숨기지 말고 그 자체를 이야깃거리로 쓴다.
  예: "물고기를 주지 말고 낚시를 가르쳐라"는 탈무드에 없다(19세기 영국 소설이 첫 확인), "탁월함은 습관이다"는 윌 듀랜트의 요약이다.
  배경을 쓰기 전에 **`quote`와 `source`가 서로 맞는지** 먼저 본다 — CLQ_125는 "붕새"가 "푸른 닭"으로 잘못 들어가 있었다.
- **명사 어록(아인슈타인·트웨인·간디·다빈치 등)은 대부분 원출처가 없다.** 넣기 전에 원출처를 확인하고, 없으면 배경에 그 사실과 "실제로 한 비슷한 말/한 일"을 쓴다(예: 간디 → 1918년 노동운동가 니컬러스 클라인의 연설).
- `source`의 책 이름이 맞는지도 본다 — 괴테 "재능은 고요 속에서"는 《빌헬름 마이스터》가 아니라 《토르콰토 타소》, "진실은 순수하지 않다"는 《진지함의 중요성》이었다.
- 150~250자.

### 작성 프롬프트
```
SJ 아카이브 "오늘의 고전"에 backstory(배경·일화) 필드를 채운다. JSON 한 덩어리만 출력.
- 대상: public/data/work_db/classic_quotes*.json 의 classic_quotes
- 출력 형식: { "CLQ_###": "배경 문장", ... } — id를 키로 하는 객체 하나
- 각 150~250자. context(직장 적용)와 내용이 겹치면 안 된다.
- 반드시 담을 것: 저자가 어떤 처지였는지 / 이 말이 나온 장면 / 기억에 남을 구체적 사실 하나
- 후대 전승·일화는 "전해진다"로 명시. 확실하지 않은 사실은 쓰지 않는다.
```

## 4-B. 평면 영어 풀 뉘앙스 (전량 완료 · 새 표현은 뉘앙스 포함해서 넣을 것)

> **왜:** 테마팩에는 `nuance`가 100% 있는데 평면 풀에는 0%였다. 테마·레벨에 맞는 팩이 없으면 Tier 2(평면 풀)로 떨어지는데,
> 이때 사용자는 뉘앙스 없는 얇은 카드를 받았다.

### 진행 상황 (2026-09-26 완료)

| | 개수 |
|---|---:|
| 평면 풀 전체 | **384** (정확일치 중복 119 + 근사 중복 85개 제거 후) |
| 뉘앙스 있음 | **384 — 전량** |
| `example_ko` 있음 | **384 — 전량** (09-26 batch_15·16 54개 채움) |

> ⚠️ **근사 중복이 가장 큰 함정이었다.** 같은 관용구가 문장형(“Let's get the ball rolling.”)과 원형(“Get the ball rolling”)으로 여러 배치에 흩어져 있었고,
> 정확일치 검사로는 하나도 안 잡혔다. 불용어(I/it's/let's/the…)를 뺀 핵심어 집합이 80% 이상 겹치면 같은 표현으로 보고 하나만 남겼다.
> **새 표현을 넣기 전에 반드시 같은 방식으로 기존 풀과 대조할 것.** 단, 뜻이 다른 쌍은 남긴다
> (over my head≠in over my head, keep in the loop≠loop in, What's your bottom line?(협상 최저선)≠bottom line).

### 작성 기준

- **뜻풀이(`meaning`)와 겹치지 않게 쓴다.** 뜻은 이미 위 칸에 있다.
- 담을 것: **언제 쓰면 안 되는지 / 비슷한 표현과 뭐가 다른지 / 한국인이 어디서 틀리는지.**
- 구어·미드 표현은 **톤과 관계가 뜻을 바꾼다** — 억양에 따라 의미가 갈리면 반드시 적는다.
- ⚠️ **같은 표현의 변형이 여러 파일에 흩어져 있다**(예: "I'm swamped"/"I'm totally swamped", "Let me sleep on it"/"I need to sleep on it"). 정확일치 중복 제거로는 안 잡히니, 뉘앙스를 쓰기 전에 다른 배치에 같은 핵심어가 있는지 확인하고 하나만 남긴다.
- 분량 **120~180자**. 테마팩 평균이 165자이므로 그 언저리면 자연스럽다.
- 어원·출처는 정확할 때만(예: Touché는 펜싱 프랑스어, "You had me at hello"는 제리 맥과이어).
  확실하지 않으면 쓰지 않는다.

### 작성 프롬프트
```
SJ 아카이브 평면 영어 표현에 'nuance' 필드를 채운다. JSON 한 덩어리만 출력.
- 대상 파일: public/data/knowledge_db/<파일명>의 english_expressions
- 출력 형식: { "EN_###": "뉘앙스 문장", ... } — id를 키로 하는 객체 하나
- 각 뉘앙스는 120~180자. meaning과 내용이 겹치면 안 된다.
- 반드시 담을 것: 언제 쓰면 안 되는지 / 비슷한 표현과의 차이 / 톤에 따른 의미 변화
- 확실하지 않은 어원·출처는 쓰지 않는다.
```

> ⚠️ 평면 풀은 **SQLite가 아니라 JSON에서 직접 읽는다**(`loadKnowledgeDB()`가 모듈 캐시).
> 그래서 마이그레이션 없이 파일만 고치면 되지만, **서버 재시작(=배포) 전까지는 반영되지 않는다.**

## 4-D. 오늘의 구문 (english_patterns) — 09-28 신설

> 사용자 요청: "I'm not sure I should ~ 같은 표현이 언제 어떻게 쓰이는지 알려 주면 좋겠다." 표현(통째로 외우는 말)·단어와 **별개 트랙**으로, 영어 카드에 하루 한 장 붙는다(`patternEntry`, `_pickDailyPattern`, 120일 중복 창).

- 스키마: `{ id:"PT_###", pattern, meaning, level(beginner|intermediate|advanced), register(daily|business|any), when, structure, examples:[{en,ko}×3], mistake, similar }`
- **when**(언제 쓰나)·**mistake**(흔한 실수 — 어순·전치사·to/-ing)·**similar**(비슷한 틀과 강도·격식 차이)가 이 트랙의 존재 이유다. 셋 중 하나라도 비면 넣지 말 것.
- 앱: 앞면(틀·뜻·언제·형태·예문1) / "예문 더 보기 · 흔한 실수"로 펼침. 연대기·서재 상세에도 표시.
- 09-28 기준 30개(초10·중12·고8, batch_64). 다음 후보: I was going to ~ but / I'd better ~ / It depends on ~ / I feel like ~ing / Don't bother ~ing / There's no way ~ / I'm dying to ~ / I wish I had ~ / If I were you ~ / Not to mention ~.

## 4-C. 영어 단어 트랙 (english_words)

> **표현(english_expressions)과 별개 트랙.** 기존 813개 중 단어는 3%뿐이라 어휘 확장 기능이
> 사실상 없었다. 2026-09-20에 신설.

### 왜 별도 피드가 아닌가
배달 피드를 6개 → 3개로 줄인 방향을 되돌리지 않기 위해, **영어 카드 하단 섹션**으로 넣는다.
`wordEntries` 배열이 영어 피드에 실려 오고 `Mob._renderWordTrack()`이 그린다.
Tier 1(테마팩)·Tier 2(평면 풀) **양쪽 경로 모두**에 붙어 있어야 한다 — 한쪽만 붙이면
평면 풀로 떨어진 사용자만 단어를 못 받는다.

### 핵심: 단어는 뜻만으론 못 쓴다
`collocations`(어떤 말과 붙는가)와 `confusable`(헷갈리는 단어와 뭐가 다른가)이 이 트랙의 존재 이유다.
이 두 칸이 비면 그냥 단어장이 되고, 사전보다 나을 게 없어진다.

### 현재 재고

| 레벨 | 개수 |
|---|---:|
| beginner | 35 |
| intermediate | 42 |
| advanced | 43 |
| **합계** | **160** (하루 3개 → 약 53일치 · 09-28 batch_63에서 뉴스 20·일상 20 추가) |

> **09-28부터 `domain` 필드 필수**: `news`(📰 뉴스·헤드라인) / `daily`(💬 일상 대화) / `business`(💼 비즈니스). 하루 3개를 **영역별로 하나씩** 뽑아 카드에 "📰 뉴스 · 중급" 뱃지로 보여 준다(`_pickDailyWords`). 현재 business 99 · news 29 · daily 32 — **news·daily를 더 채워 균형을 맞출 것**(특히 news 초급 7·daily 고급 6). 뉴스 초급은 "헤드라인에서만 다르게 쓰는 짧은 단어"(hike·vow·slam·probe·bid)가 핵심.
> ⚠️ 09-28 점검에서 `getRecentDeliveredIDs`가 wordEntries를 모으지 않아 단어 중복 방지가 **아예 안 되고 있던** 버그를 고쳤다(구문도 함께).

> ⚠️ **레벨을 고르게 유지할 것.** 한 레벨이 3개 미만이면 `_pickDailyWords`가 전체 풀로
> 폴백해서, 초급 사용자에게 `reconcile`·`marginal` 같은 고급 단어가 나간다(실제로 겪은 문제).
>
> 초급은 **어려운 단어를 쉽게 쓰는 게 아니라, 쉬운데 잘못 쓰는 단어**를 다룬다 —
> `check with` vs `confirm`, `set up a meeting`(make가 아님), `figure it out`(어순) 같은 것들.

### 생성 프롬프트
```
SJ 아카이브 직장인 배달 "영어 단어"를 생성한다. JSON 한 덩어리만 출력, 설명 금지.
- 위치: public/data/knowledge_db/ 의 .json, 최상위 키 "english_words"
- id: WD_<다음 번호>부터 전역 고유(현재 다음 WD_121). 단어 10~20개.
- 주제: <여기에. 예: "회의·보고에서 자주 쓰는 동사">
- **기존 표현 풀과 겹치지 않게 할 것** — 이미 english_expressions에 있는 단어는 피한다.
- collocations는 실제로 자주 붙는 3개. 사전식 나열이 아니라 통째로 외워 쓸 덩어리로.
- confusable은 **비슷해서 틀리는 단어**와의 차이를 구체적으로. 없으면 이 단어를 고르지 말 것.
- nuance는 언제/왜 쓰는지, 한국인이 어디서 틀리는지. 120~180자.
- level은 beginner|intermediate|advanced 중 하나.
스키마:
{ "meta":{"topic":"...","created":"YYYY-MM-DD"},
  "english_words":[ {"id":"WD_###","word":"streamline","pos":"동사","meaning":"뜻 한 줄",
    "level":"intermediate","collocations":["...","...","..."],
    "confusable":"비슷한 단어와의 차이 2~3문장","nuance":"쓰임 120~180자",
    "example":"영어 예문","example_ko":"한국어 번역"} ] }
```

## 4-E. 깊이 읽기 · 연재 (deep_layers) — 10-05 신설

**왜**: 사용자 피드백 "아침마다 지식 한줌을 보는데 글이 부족하다, 유식해진다는 느낌이 없다." 실제 카드 본문은 ~450자(무슨 일 + 비하인드)뿐이었다.
**어디**: `public/data/deep_layers/*.json` — 원본 항목(history_facts·classic_quotes·idiom_cards·daily_insights)은 그대로 두고 **id로 겹쳐 얹는다**. 서버가 폴더 전체를 읽어(`loadDeepLayers`) 배달 객체에 `deep`을 붙인다.

```json
{ "series": [ { "id": "greece", "title": "고대 그리스", "items": ["HI_424", "HI_344", "..."] } ],
  "deep": { "HI_345": {
      "lesson": "한 줄 통찰(카드 앞면, 50자 안팎)",
      "background": "그때 판 — 이 일이 일어나기 직전의 상황·사람·제도 (200~300자)",
      "terms": [ { "t": "용어", "d": "지금도 쓰이는 말·어원 위주 설명(60자 안팎)" } ],
      "after": "그 후, 그리고 지금 — 결과·후대 영향·오늘 남은 흔적 (200~300자)",
      "talk": "써먹는 한마디 — 대화·회의에서 그대로 꺼낼 수 있는 1~2문장(존댓말)" } } }
```
- **terms는 정확히 3개.** 다섯 칸 모두 필수.
- **원본의 summary/behind_story/origin/backstory/body와 겹치는 내용 금지** — 깊이 읽기는 '그 다음 층'이다.
- **사실 검증 필수**: 연도·숫자·인용은 출처가 확실한 것만. 불확실하면 '~라고 전한다', '논쟁 중'으로 쓴다(예: 이에야스 유훈은 후대 창작 가능성, 던닝-크루거 그래프는 원 논문에 없음).
- **연재(series)**: 역사 항목만. 시간 순서로 묶고, `after` 끝에서 다음 편으로 다리를 놓으면 이어 읽는 맛이 산다('다음 편에서…'). 마지막 편 `after`에는 '— ○○ 연재는 여기까지.'
- 배달 규칙(server.js `_pickSeriesItem`): 진행 중인 연재의 **안 본 첫 편** → 안 끝난 첫 연재(파일·배열 순서) → 연재 밖이면 깊이 읽기 있는 항목 우선 → era 항목 → 전체. 지혜(고사성어·고전·인사이트)도 깊이 읽기 있는 항목이 먼저 나간다.
- 카드: 앞면 `lesson`, 펼치면 그때 판 → (원본 비하인드) → 오늘 알게 된 말 → 그 후 → 써먹는 한마디, 맨 아래 '다음 편' 예고. 서재 상세(home.js)·연대기(chronicle.js)에도 같은 칸이 나온다.

### 현재 재고 (10-05)
| 파일 | 내용 |
|---|---|
| `01_greece_rome.json` | 연재 그리스 10편(솔론→소크라테스) · 로마 공화정 14편(한니발 알프스→토이토부르크, 파비우스 HI_355는 이미 배달돼 깊이 읽기 없음) |
| `02_goryeo_sengoku.json` | 연재 고려 10편(서희→팔만대장경) · 일본 전국시대 12편(모리 세 화살→두견새) |
| `03_wisdom.json` | 고사성어 10 · 고전 10 · 인사이트 10 |

→ 역사 연재 45일치(10-06~11-19), 지혜 30일치. **11월 중순 전에 다음 연재를 넣어야 한다**(후보: 중국 춘추전국→진·한, 조선 전기, 대항해시대, 프랑스 혁명~나폴레옹, 삼국시대).

### 작성 프롬프트
```
아래 역사 항목(id·제목·summary·behind_story)을 읽고 deep_layers 스키마로 '깊이 읽기'를 써줘.
- lesson / background / terms(정확히 3개) / after / talk
- 원본과 겹치는 내용 금지, 그 사건 직전의 판(background)과 그 후·오늘의 흔적(after)에 집중
- 용어는 지금도 쓰이는 말·어원 위주. 숫자·연도·인용은 확실한 것만, 불확실하면 '전한다'
- 연재라면 after 끝에서 다음 편으로 다리를 놓을 것
- 문체: 본문은 '~다', talk만 존댓말
```
